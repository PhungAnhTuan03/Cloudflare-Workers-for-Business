Báo cáo quá trình dự án

Quá trình tạo website và kế hoạch chuyển backend sang FastAPI Python

Tài liệu mô tả cách website Sao Việt Tech Academy được xây dựng, các hạng mục đã triển khai, những việc cần làm tiếp và các khó khăn dự kiến khi tách backend sang FastAPI.

Frontend hiện tại Astro 6 + React 19 + Tailwind CSS 4
Backend hiện tại Astro API Routes + Cloudflare Workers
Backend dự kiến FastAPI Python

1. Mục tiêu ban đầu của dự án

Dự án được xây dựng với mục tiêu tạo một website trung tâm đào tạo công nghệ hiện đại, có khả năng làm website marketing, cổng tư vấn, marketplace khóa học, dashboard học viên, dashboard giảng viên, trang profile và trang admin quản trị tổng thể.

Sản phẩm Website đào tạo công nghệ

Giới thiệu thương hiệu, khóa học, giảng viên, tin tức, liên hệ và đăng ký tư vấn.

Kinh doanh Bán khóa học

Giảng viên đăng khóa học, học viên xem marketplace, thêm giỏ hàng, mua khóa và nhắn tin riêng.

Vận hành Admin quản trị

Theo dõi lead, người dùng, khóa học, chứng chỉ, chi nhánh, nội dung và dữ liệu vận hành.

  1. Thiết kế quyền chi tiết hơn cho admin, editor, tư vấn tuyển sinh, kế toán, quản lý đào tạo.
  2. Kết nối cổng thanh toán thật, xử lý webhook, trạng thái đơn hàng và hoàn tiền.
  3. Thêm quản lý đơn hàng, hóa đơn và báo cáo doanh thu theo thời gian.
  4. Chuẩn hóa upload tài liệu, kiểm duyệt file, giới hạn dung lượng theo role.
  5. Bổ sung test e2e cho các flow: đăng ký, đăng nhập, đăng khóa học, mua khóa, chat, admin update.
  6. Thêm logging, error tracking, backup database và tài liệu vận hành.
  7. Tối ưu SEO nâng cao: sitemap động, schema Course/Article/FAQ, internal linking, local landing page.

6. Dự định chuyển backend sang FastAPI Python

Hiện tại backend nằm trong Astro API routes chạy trên Cloudflare Workers. Hướng phát triển tiếp theo là tách backend nghiệp vụ sang FastAPI Python để dễ mở rộng các module phức tạp như thanh toán, báo cáo, AI recommendation, queue xử lý nền, phân quyền nâng cao và tích hợp hệ thống bên ngoài.

Mục tiêu Tách business API

Astro giữ vai trò frontend SSR, FastAPI phụ trách auth, user, course, order, lead, chat, admin API.

Dữ liệu Chọn database phù hợp

Cân nhắc PostgreSQL cho production để migration, relation, analytics và transaction mạnh hơn D1.

Triển khai API riêng

Deploy FastAPI trên VPS, Docker, Fly.io, Render, Railway hoặc Cloud Run; frontend gọi qua HTTPS API.

7. Kiến trúc đề xuất khi chuyển sang FastAPI

Lớp hệ thống Hiện tại Sau chuyển đổi
Frontend Astro SSR + Astro API routes Astro SSR gọi FastAPI qua service client
Auth Cookie session + KV + D1 FastAPI quản lý session/JWT, refresh token, RBAC
Database Cloudflare D1 SQLite PostgreSQL hoặc tiếp tục D1 qua adapter nếu bắt buộc
Upload Astro API upload lên R2 FastAPI cấp signed URL hoặc upload proxy lên R2/S3
Email Resend gọi trong Astro API FastAPI background task/queue gọi Resend
Admin Astro page + API local Astro admin UI gọi FastAPI admin endpoints
CMS EmDash trong Astro Giữ EmDash cho editorial hoặc tách CMS API riêng tùy phạm vi

8. Khó khăn khi chuyển đổi backend

Khó khăn Khác biệt runtime

Cloudflare Workers chạy edge runtime, FastAPI chạy Python server runtime. Các API về request, cookie, crypto, file upload, env và streaming sẽ phải viết lại.

Khó khăn Di chuyển authentication

Session hiện dùng cookie và KV. Khi chuyển sang FastAPI cần quyết định dùng JWT hay server session, cách đồng bộ đăng nhập với Astro SSR và chống CSRF.

Khó khăn Migration database

D1 dùng SQLite. Nếu chuyển sang PostgreSQL phải chuyển schema, dữ liệu, index, constraint, kiểu thời gian và transaction.

Khó khăn R2 và file upload

FastAPI cần cấu hình boto3/S3-compatible client, signed URL, giới hạn dung lượng và bảo mật file.

Khó khăn API contract

Frontend hiện đang gọi nhiều Astro API. Cần giữ response shape tương thích hoặc viết adapter để không phá UI.

Khó khăn Triển khai và vận hành

FastAPI cần server/container, reverse proxy, domain, SSL, logging, monitoring, scaling và backup riêng.

9. Chiến lược chuyển đổi an toàn

  1. Đóng băng API contract hiện tại bằng tài liệu OpenAPI hoặc file mô tả endpoint.
  2. Tạo FastAPI project riêng với module auth, users, leads, courses, orders, messages, admin.
  3. Viết database schema bằng SQLAlchemy/Alembic, ưu tiên PostgreSQL nếu làm production dài hạn.
  4. Triển khai song song: Astro API cũ vẫn chạy, FastAPI mới chạy ở subdomain như api.example.com.
  5. Chuyển từng nhóm API: auth trước, sau đó lead, marketplace, cart, instructor, admin.
  6. Frontend Astro gọi qua service layer để có thể đổi backend mà không sửa từng component.
  7. Chạy migration dữ liệu thử nghiệm, kiểm tra số lượng record, khóa ngoại và dữ liệu người dùng.
  8. Chạy e2e test cho từng flow trước khi tắt API cũ.
  9. Sau khi ổn định, chỉ giữ Astro API cho các route nhẹ hoặc proxy cần thiết.

10. Mapping module từ Astro API sang FastAPI

Module hiện tại FastAPI router đề xuất Ghi chú chuyển đổi
/api/auth/* /auth/register, /auth/login, /auth/me Ưu tiên làm đầu tiên vì liên quan toàn hệ thống.
/api/business/leads /leads Giữ validate số điện thoại, email, source path, UTM.
/api/marketplace/courses /courses Chuẩn hóa filter, sort, pagination, SEO slug.
/api/cart /cart, /checkout Cần transaction tốt nếu thêm thanh toán thật.
/api/instructor/* /instructor/courses, /instructor/materials Cần role guard instructor và ownership check.
/api/admin/* /admin/overview, /admin/users, /admin/leads Cần RBAC chi tiết và audit log chặt hơn.
/api/upload /uploads/presign Nên dùng signed URL để giảm tải server Python.

11. Roadmap đề xuất

Tuần 1
Chuẩn hóa tài liệu và API contract

Tuần 3
Chuyển auth, user, profile

Di chuyển đăng ký, đăng nhập, profile, role và session/JWT.

Tuần 4
Chuyển marketplace và instructor

Di chuyển khóa học, bài giảng, tài liệu, giỏ hàng, mua khóa và coupon.

Tuần 5
Chuyển admin và reporting

Di chuyển admin overview, lead, user, course, audit log và dashboard báo cáo.

Tuần 6
Kiểm thử, migration và cutover

Chạy e2e, migrate dữ liệu, so sánh dữ liệu, deploy staging, sau đó chuyển production.

12. Kết luận

Website đã đạt được nền tảng quan trọng: public website, auth theo role, marketplace khóa học, dashboard học viên, dashboard giảng viên và admin center. Việc chuyển backend sang FastAPI là hướng đi hợp lý nếu dự án cần mở rộng logic nghiệp vụ, báo cáo, thanh toán, AI hoặc tích hợp hệ thống bên ngoài.

Khuyến nghị: không nên chuyển toàn bộ backend một lần. Nên chuyển từng module theo API contract, chạy song song một thời gian và chỉ cutover khi e2e test cùng dữ liệu migration đã ổn định.
